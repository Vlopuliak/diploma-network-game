## Обсяг · погоджено користувачем 2026-11-19

## Реалізація

[CopyDecisionAgent](../Assets/Scripts/AI/TheCopy/CopyDecisionAgent.cs) успадковує Unity.MLAgents.Agent. [CopyDecisionAgentHost](../Assets/Scripts/AI/TheCopy/CopyDecisionAgentHost.cs) є NGO NetworkBehaviour й керує його життєвим циклом. Чинний CopyDecisionInputV2 збирає 50 ознак і кандидатів.

- До мережевого spawn та на клієнтських репліках Agent вимикається **до** base.OnEnable, не створює model runner і не реєструє клієнт у Academy. На сервері host-компонент активує його після spawn. Base.OnDisable викликається лише після фактичної ініціалізації. Despawn або вимкнення host-компонента вимикає Agent та очищає pending-знімок.
- Конфігурація потребує Model, BehaviorType.InferenceOnly, 50 векторних ознак, stacking 1, нуль неперервних дій та одну дискретну гілку 7. Неявного переходу до HeuristicOnly немає. Налаштовувати BehaviorParameters і Model слід до spawn. Конкретну модель потрібно окремо перевірити за сигнатурою; перевірка BehaviorParameters сама по собі не доводить семантику ONNX.
- TryRequestDecision дозволений тільки активному spawned-серверному NPC з доступним CopyDecisionInputV2. Одночасно допускається один запит. Ознаки й кандидати захоплюються **один раз до RequestDecision**. CollectObservations і WriteDiscreteActionMask використовують той самий знімок, не читають світ незалежно.
- OnActionReceived перевіряє авторитетність, конфігурацію, формат гілки, індекс, маску захопленого знімка та поточну доступність цілі. Відповідь старша за 0,5 scaled секунди відкидається. Для цільової дії ID та позиція мають збігатися із повторною перевіркою; переміщення або втрата цілі відхиляє стару відповідь. Це консервативна перевірка: слідування за рухомою ціллю потребуватиме окремої політики Action Controller.
- Прийнятий результат публікується локально на сервері через DecisionAccepted(action, target). Немає запису у NetworkVariable механізмів, руху NPC, reward чи мережевої реплікації наміру. Це ще не Action Controller. Дії 5/6 закриті масками draft-2.
- Automatic Decisions початково False. Після налаштування моделі можна явно викликати TryRequestDecision або ввімкнути цей прапор для запитів раз на 0,2 с за замовчуванням. Без кроків Academy відповідь не надійде; одночасно pending-запити не накопичуються. У тесті Academy крокує вручну, у звичайному Play використовується стандартний автоматичний цикл ML-Agents.
- Якщо базовий reset Academy скасовує pending-запит, транспортна маска залишає лише Continue, щоб не подавати ML-Agents порожню гілку. Така відповідь не публікується, бо pending-знімка немає. Це не вибір ігрової дії C#-політикою.

Сумісність із server-only перевірено на окремих NGO Host/Client менеджерах. Тест не доводить роботу Relay, host migration або продуктивність на цільовій збірці.
