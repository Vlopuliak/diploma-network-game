# P4-03 · Зафіксований контракт sensory-intent-v1

## Погоджений обсяг

2026-11-19 користувач обрав: «Спочатку вибір наміру за реальними сенсорами, 0–4, без руху; окремо оцінити цю обмежену задачу».

Це **однокроковий вибір наміру** з поточного сенсорного знімка. Кожен навчальний випадок має окремо підготовлений стан і одне рішення. Нейромережа не керує рухом, не перемикає механізми та не завершує багатокрокову головоломку. Відповідні висновки про поведінку в кооперативній грі з цього експерименту не робляться. Reward та метод оцінювання належать наступній P4-04 і тут не підміняються готовим oracle.

Попередній намір і стан виконання дії **не додаються** до цього однокрокового контракту: у ньому немає виконання чи продовження попередньої дії. Для багатокрокового сценарію це рішення потрібно переглянути перед навчанням, з новою версією контракту за зміни ознак. Пам’ять звуку залишається реальним вхідним сенсорним станом.

P4-03 завершено **в межах цього погодженого першого сценарію**. Повна production-поведінка NPC, навчання, навігація, адаптивність, фізична допомога та етап 4 загалом не завершені.

## Зафіксовані 50 ознак

Порядок перших 40 ознак збережено за [draft-1](AI_NPC_DECISION_INPUT_DRAFT.md), реалізовано спільним CopyDecisionEncoder.TryEncodeCore:

- **0–11 — live-звук:** наявність, сила, freshness, локальні X/Y/Z і відстань, чотири one-hot категорії шуму, наявність визначеного джерела.
- **12–23 — звукова пам’ять:** ті самі 12 ознак у тому самому порядку.
- **24–30 — світло:** наявність, сила, локальні X/Y/Z і відстань, IsAimApproximate.
- **31 — рівність визначених SourceClientId останнього відомого звуку та світла.** Анонімне джерело не дорівнює Host ID 0.
- **32–39 — контекст:** пари known/value для ZoneTriggered, PowerOn, AirlockOpen, KeypadUnlocked. Відомий False = [1, 0], True = [1, 1], unknown = [0, 0].
- **40–44 — A:** поточна видимість, локальні X/Y/Z, відстань.
- **45–49 — B:** ті самі п’ять ознак.

Усі позиції кодуються відносно root NPC у його локальних осях. X/Y/Z поділені на сталу 18 та обмежені до [-1, 1], відстань від root — до [0, 1]. Відсутній сигнал/гравець дає нульовий блок; видимість = 0 відрізняє від видимого гравця зі збігом позицій. Метадані сенсора можуть мати відстань від ока, але числовий вектор використовує root. Сили й freshness належать [0, 1]. Некоректні числові значення, несумісна довжина або дубльований гравець у A/B не приймаються. Сенсорні дані гравців повинні мати час поточного знімка.

Параметри сенсорів налаштовуються окремо й мають фіксуватися в конфігурації навчальних випадків. Значення 18 у нормалізації контракту не змінюється через зміну радіуса сенсора в Inspector.

## Цілі, маски та авторитетність

0 Continue — дозволений для коректно захопленого стану, окремої цілі немає. 1 InvestigateSound отримує останню почуту позицію зі спогаду або live-сигналу. 2 InvestigateLight доступний для поточного світла з отриманою сервером позою камери. 3 ObservePlayerA та 4 ObservePlayerB доступні лише за поточної видимості свого слоту; ціль — копія сприйнятої позиції центра CapsuleCollider та ID джерела. 5 AssistMechanism і 6 ObstructMechanism **зарезервовані й завжди закриті** в цьому сценарії.

A/B призначаються за зростанням підключених Client ID при першому читанні, потім залишаються стабільними незалежно від видимості. Disconnect звільняє тільки свій слот; живий учасник не переставляється, нове підключення займає вакансію. Ціль не визначається порядком видимих об’єктів. Механічні стани контексту не є дозволом на взаємодію.

Весь захоплений вектор і його маски належать одному серверному рішенню. Невдале читання очищає вектор; його не можна подавати моделі. Клієнт не отримує серверного входу та не ініціалізує Agent. Відповідь перевіряється повторно; за втрати/зміни цілі або віку понад 0,5 scaled секунди відкидається. Прийнятий намір поки лише публікується серверною подією, не виконується у світі.

## Перевірка призначеної моделі

Додано [CopyDecisionModelValidator](../Assets/Scripts/AI/TheCopy/CopyDecisionModelValidator.cs). Перед base.OnEnable Agent завантажує структуру ModelAsset та перевіряє рівно два float-входи: obs_0 [batch, 50] і action_masks [batch, 7]. Batch може бути динамічним або 1. Потрібні імена ML-Agents-виходів discrete_actions, discrete_action_output_shape, version_number, memory_size. Відсутні, дубльовані, зайві, цілочислові входи, невідома чи стара ширина відхиляються. Результат кешується для призначеного ModelAsset; модель налаштовують до spawn, зміна потребує вимкнення/увімкнення host-компонента.

Це структурний guard, **не перевірка семантики ваг**, не повна валідація усіх вихідних тензорів і не доказ якості політики. 50-вхідна модель з іншим значенням ознак може мати таку саму сигнатуру; потрібні парний контракт, metadata та offline preflight. Runtime ModelAsset не використовується як заміна provenance-журналу. Остаточні ML-Agents output/API перевірки залишаються за його завантажувачем і тестом фактичного inference.

Старі Stage4 на 27 входів та експортовані раніше smoke-моделі з draft-2 SchemaId не є артефактами цього зафіксованого експерименту. Не відновлювати з них checkpoints. Тестовий exporter тепер читає схему з JSON, а не має власний застарілий рядок.
