# P4-03 · NPC-API першого рубильника

## Обсяг і критерії

2026-11-19 користувач погодив точкову зміну спільного `NetworkInteractiveObject`. Результат — серверний NPC встановлює потрібний стан явно призначеного рубильника без підміни гравця. Відмова не змінює стан; успішна зміна зберігає чинні події живлення, зв’язок зі шлюзом і шум. Перевіряються власник NPC, відстань, спільний cooldown, дозволи адаптера та реплікація.

Файли: [NetworkInteractiveObject](../Assets/Scripts/Interaction/NetworkInteractiveObject.cs), [CopyPowerInteraction](../Assets/Scripts/AI/TheCopy/CopyPowerInteraction.cs), [сценові перевірки](../Assets/Tests/AI/P403NpcInteractionVerification.cs), [мережеві перевірки](../Assets/Tests/AI/P306PerceptionVerification.cs).

## Контракт

`CanSetActiveFromNpc(NetworkObject npc, bool active)` і `TrySetActiveFromNpc` працюють лише на активному серверному spawned-рубильнику. Актор має бути spawned, належати серверу, бути з того самого NetworkManager, не бути PlayerObject та мати активний `CopyPerception`. Відстань перевіряється до NPC за `maxServerInteractDistance` рубильника, а не до гравця Host. Нескінченні відстані та NaN відхиляються.

Реальна зміна використовує спільний із player-RPC `_lastToggleTime` та спільний `ApplyState`. Повтор коректного запиту на вже встановлений стан повертає True без події, шуму та продовження cooldown. Це не RPC; сервер викликає API безпосередньо. Перевірки наявного player-RPC збережені.

`CopyPowerInteraction` — серверний адаптер на NPC з явним `target`. Прапори `allowPowerOn` і `allowPowerOff` початково False. Це дозвіл напрямку взаємодії, а не визначення вигоди Assist/Obstruct. Кандидат містить NetworkObjectId, позицію призначеного вузла, потрібний стан і `CanInteractNow`. Кандидат поза дистанцією або під час cooldown може існувати, але виконання заборонене. Перед дією перевірки повторюються. За вже потрібного стану кандидат відсутній і `TryApply` повертає False.

Призначений вузол є явно відомою сценарною ціллю. Глобального пошуку механізмів немає. API не перевіряє NavMesh, стінку між NPC і рубильником чи правила конкретного пазла понад чинну дистанційну перевірку рубильника. Ці правила потрібні перед production-використанням.

## Відтворення

У PowerShell із кореня репозиторію:

```powershell
.\tools\Verify-P305.ps1 -VerifyNpcInteraction -KeepWorkspace
.\tools\Verify-P305.ps1 -UseWebSockets -VerifyPerception -KeepWorkspace
```

Перший запуск компілює копію проєкту й створює копію Networking_Sandbox з адаптером на NPC, прив’язаним лише до Interactive_Terminal. Дозволи змінюються тестом у пам’яті. Сцени вихідного проєкту не змінюються. Прогін включає тести знімка та чернетки ML-входів. Другий запускає NGO Host/Client через локальний UTP WebSocket в одному Unity-процесі з окремими NetworkManager. Це автоматична інтеграційна перевірка, а не два standalone-процеси чи Relay.

22 сценові перевірки охоплюють заборону за замовчуванням, кандидата, null/PlayerObject/unspawned/disabled, дистанцію, незмінність після відмов, NPC поблизу при віддаленому Host, події й шум рівно один раз, шлюз, контекст, пам’ять, ідемпотентність, спільний cooldown в обох напрямках, відкликання дозволу та відсутню ціль. Мережеві доповнення перевіряють клієнтський API, іншого NetworkManager, немаркований об’єкт, власність клієнта, вимкнений вузол і підтверджений перехід стану на клієнті після дії NPC.
