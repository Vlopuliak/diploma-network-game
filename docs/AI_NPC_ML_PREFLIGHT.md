## Обсяг і критерії · 2026-11-19

Продовження draft-2 без змін пакетів командної гри. Результат: відтворювана перевірка C#/JSON/YAML-контракту, справжнього trainer-парсера, метаданих Unity-пакетів, замикання залежностей за локальним тестовим проєктом і структури старого ONNX. Критерій — фактичні докази, які відділяють коректний формат від готовності виконувати нейромережу в грі.

- За ML-залежностями lock-файла тестового проєкту новими для командної гри є **com.unity.ml-agents 4.1.0**, **com.unity.ai.inference 2.6.1**, **com.unity.dt.app-ui 2.2.4**. - Ідентифікатор пакета inference — саме **com.unity.ai.inference**. Namespace API — Unity.InferenceEngine. Підставляти вигадану назву пакета `com.unity.inference-engine` не потрібно.

Повний локальний доказ: [JSON preflight](../Logs/AI-NPC/P4-03-ml-preflight-20261119.json). `ready_for_game_inference=False`, очікуваний exit code **2** означає наявність блокерів готовності, а не успішний inference. Exit 1 означає помилку самої перевірки. Поки Agent/inference не реалізовані, інструмент явно фіксує це як блокер; він не є майбутнім універсальним тестом виконання моделі.

## Як відтворити

Локальний приклад для поточного комп’ютера, PowerShell із кореня репозиторію:

```powershell
$mlPython = 'D:/PROGS/anaconda3/envs/project-s-ml/python.exe'
& $mlPython -B -m unittest discover -s tools/tests -v
& $mlPython -B tools/verify_ai_npc_ml.py --mlagents-package 'D:/PNU/4kurs/diploma/ai-test/Library/PackageCache/com.unity.ml-agents@51fac9654958' --inference-package 'D:/PNU/4kurs/diploma/ai-test/Library/PackageCache/com.unity.ai.inference@9a123aee5df7' --reference-project 'D:/PNU/4kurs/diploma/ai-test' --model 'D:/UnityML/ml-agents/results/projectS-stage4-s11-retry/ProjectSStage4.onnx' --output 'Logs/AI-NPC/P4-03-ml-preflight-20261119.json'
```

Шляхи PackageCache є локальними аргументами перевірки. У manifest гри їх додавати не можна. Скрипт приймає інші шляхи для іншого комп’ютера. Доступ до Інтернету для цього прогону не використовувався.

## Конкретна пропозиція наступної зміни — потребує погодження

1. Для першої Agent/inference-перевірки використати **поточний draft-2: 50 входів, stacking 1, дискретна гілка [7]**, доступні лише сенсорні наміри 0–4 за масками. Дії 5/6 лишаються закритими. Це не фінальне затвердження reward та gameplay-навчання.
2. Спочатку в тимчасовій копії додати registry-залежності **com.unity.ml-agents 4.1.0** та **com.unity.ai.inference 2.6.1**, виконати UPM-resolve. Очікується новий транзитивний App UI; за reference lock — 2.2.4. Перевірити Packages/packages-lock.json. Якщо потрібна зміна версії будь-якого вже наявного пакета, зупинитися з конкретним diff до зміни робочого проєкту.
3. Перевірити компіляцію, потім застосувати перевірені зміни **лише Packages/manifest.json та Packages/packages-lock.json** у робочій ai-branch. Не переносити manifest тестового проєкту цілком і не посилатися на абсолютні локальні шляхи.
4. Додати NPC-адаптер Agent та серверне керування його життєвим циклом. CollectObservations має використовувати один захоплений draft-2 разом із його масками; не захоплювати різні знімки незалежно для вектора й масок. Запити рішення й приймання дії дозволені тільки на spawned-серверному NPC. Після despawn або втрати цілі стару відповідь не виконувати.
5. Перевірити 50 входів / одну гілку 7 / server-only / маски та справжнє Unity CPU-inference на окремій **ненавченій тестовій нейромережі** з відповідною сигнатурою. Таку модель можна експортувати без PPO-навчання в тимчасовій копії. Це доказ технічного з’єднання, а не адаптивної поведінки чи якості політики. Старий 27-вхідний ONNX не підключати до нового NPC.
6. Повторити поточні інтеграційні перевірки. Production-сцени та механізми напарника, reward, навігацію, довге навчання, коміти й push у цей обсяг не включати.
